# Security policy

This project is a defensive architecture and security assessment skill. It is not a penetration-testing service or an assurance certification. Current development targets the latest pre-release; no support SLA is promised.

## Reporting a project vulnerability

If private vulnerability reporting is enabled in the GitHub repository, use its Security tab to report an issue privately. Otherwise request a private channel from the maintainer using a minimal, non-sensitive public issue; do not publish vulnerability details, credentials or real target data in public issues. Include affected release, a minimal synthetic reproduction, expected behavior, impact and suggested correction. Do not test live third-party systems without explicit authorization.

The maintainers should acknowledge, triage, coordinate remediation and disclosure, and update the release and regression tests. This document proposes the process; the repository owner must enable and maintain the reporting channel.
